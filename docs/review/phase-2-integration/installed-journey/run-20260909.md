### D2 - cancellation recovery

PR #92 recorded `Cancelled` followed by an enabled `Retry`; clicking it left
the job cancelled and displayed `The scan state changed. Refresh the status
and try again.`.

In the rebuilt installed app, the cancellation fixture produced this native
transition:

```text

runId   = 01a0843d-22ce-7173-b0f7-b23eafab7b24
start   = already_running
cancel  = cancellation_requested
state   = cancelled
retryAvailable = false
errorCode = cancelled
```

The Library showed `Execution Cancelled`, the exact message
`The scan was cancelled. No new results were published.`, and only
`Scan now roots`; no Retry control was present. The existing four committed
primary rows stayed visible with their Present state.

Clicking that explicit `Scan now` created a different manual job:

```text
old job = 01a0843d-22bf-7d43-b985-658a4da09c72 (Cancelled, attempt 1/4)
new job = 01a0843d-a1a9-7001-864f-e56904dec6c5 (Completed, attempt 1/4)
```

The old cancelled job and its retry chain remained in SQLite; the new job has
a different retry chain. The 8,000-file fixture completed quickly, so the
final installed replay used the native cancel command immediately after the
visible Scan now action to avoid losing the cancellation to a completion race.
The client and native tests cover the visible queued/running Cancel path.
